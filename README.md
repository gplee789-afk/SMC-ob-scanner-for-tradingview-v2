# 台股 SMC Order Block 掃描器

每天收盤後，從成交金額最大的股票裡（可再篩選三大法人買超），找出價格正在進入 **Order Block（OB）** 的標的。整套流程只用瀏覽器和 TradingView，不需要安裝任何程式。

```mermaid
flowchart LR
    A[證交所 / 櫃買<br>每日行情＋法人（選填）] --> B[網頁版<br>排序分批]
    B -->|每批 40 檔| C[TradingView<br>OB 掃描器]
    C --> D[表格：誰在 OB 裡<br>警報：誰剛進來]
    D --> E[單一商品指標<br>看圖確認]
```

> 本專案只做 Order Block。BOS / CHoCH 只用來產生 OB，不是獨立訊號；不處理 FVG。

**名單工具（網頁版）：https://gplee789-afk.github.io/SMC-ob-scanner-for-tradingview-v2/**

第一次用 TradingView，或不熟 SMC / Order Block？先看 **[新手教學](docs/tutorial.md)**。

## 快速開始

### 1. 產生今天的名單

1. 打開網頁版 **[gplee189的排序工具](https://gplee789-afk.github.io/SMC-ob-scanner-for-tradingview-v2/)**。手機也能用，建議加入書籤。
2. 會自動載入最新一個交易日的資料（每個交易日 18:00 後更新）。想看以前的日子，用「日期」的年、月、日選單，或按 ‹ › 切換前後一個交易日、按「最新」回到今天。
3. 需要的話調整右上角的「排序依據」，或用「新高」、「產業」、「只保留三大法人買超」篩選（說明見下方「[名單工具說明](#名單工具說明)」）。不調整就是依成交金額排序。
4. 名單每 40 檔一批，按「複製」取得那批的代號。點批次標題可以展開明細，點代號或名稱會打開 Yahoo 股市的個股頁。

### 2. 把掃描器加到 TradingView

1. 打開 TradingView 圖表，點下方的「Pine 編輯器」。
2. 新建一個指標，把 `pine/smc_ob_screener.pine` 的內容整份貼上，儲存。
3. 按「加到圖表」。掃描器會出現在圖表下方的獨立窗格。

> **圖表週期必須小於或等於掃描週期。** 掃 60 分鐘就把圖表切到 1 小時（或更短）。掛在日線圖上掃 60 分鐘，結果不可靠，這是 Pine `request.security` 的限制。

### 3. 貼上代號

打開掃描器的設定（齒輪圖示），在「② 代號清單」貼上剛才複製的 40 行代號，按確定。

格式是 `交易所:代號`，一行一檔，例如 `TWSE:2330`、`TPEX:6488`。超過 40 檔的部分會被忽略。

要掃第 2 到第 10 批，就把掃描器再加到圖表一次，貼上下一批。每一份掃描器各自獨立。

### 4. 看表格

表格依「正在 OB 裡 → 距離最近 → 其他」排序，最多顯示 40 檔（預設 20 檔）。每欄 5 檔，排滿就換到右邊新的一欄，由左欄往右欄看就是由近到遠；每欄幾檔可以在設定的「③ 顯示」調整。

| 格子長這樣 | 意思 |
| --- | --- |
| `多 123.5–125.0`（綠底） | 價格正在多方 OB 裡，OB 區間是 123.5 到 125.0 |
| `空 130.0–132.5`（紅底） | 價格正在空方 OB 裡 |
| `多 ▼1.2%  125.0` | 最近的多方 OB 上緣在 125.0，還要再跌 1.2% 才會碰到 |
| `空 ▲0.8%  130.0` | 最近的空方 OB 下緣在 130.0，還要再漲 0.8% 才會碰到 |
| `–` | 目前沒有未失效的 OB |

距離在「快摸到門檻」以內（預設 2%）的格子會淡淡上色，方便提前注意。

### 5. 設定警報

1. 在 TradingView 新增警報。
2. 條件選「SMC OB Screener v5」，下方選「任何 alert() 函數呼叫」（英文介面為 **Any alert() function call**）。
3. 建立。每一份掃描器各建一個警報。

警報只在價格**從外面進入** OB 的那一根 K 棒收盤時發出。同一根裡有好幾檔同時進入，會合併成一則訊息：

```
TWSE:2330 [60] 進入多方OB 1015~1025
TPEX:6488 [60] 進入空方OB 440~452
```

OB 剛成立的那一根不會發警報，已經在 OB 裡的也不會重複發。

### 6. 看圖確認

把 `pine/smc_order_blocks.pine` 也加到圖表（這支會疊在 K 線上），切到表格裡的那一檔，就能看到 OB 區塊、BOS / CHoCH 標記和狀態面板。**記得把圖表切到跟掃描器相同的週期**，不同週期的 OB 本來就不同。

這支指標另外提供 6 種警報：進入多方 / 空方 OB、向上 / 向下結構破壞、多方 / 空方 OB 失效。

## 名單工具說明

網頁版：https://gplee789-afk.github.io/SMC-ob-scanner-for-tradingview-v2/

| 排序依據 | 算法 | 適合用來 |
| --- | --- | --- |
| 成交金額（預設） | 交易所公布的成交金額，含零股、盤後、鉅額交易 | 找當天資金最集中的股票 |
| 漲幅 / 跌幅 | 漲跌 ÷ 昨收 | 找當天最強 / 最弱的股票 |
| 振幅 | (最高 − 最低) ÷ 昨收 | 找當天波動最大的股票 |
| 法人買超金額 | 三大法人買賣超股數 × 收盤價（需三大法人資料） | 找法人實際投入最多錢的股票，不受股價高低影響 |
| 法人買超占成交量 | 三大法人買賣超股數 ÷ 成交股數（需三大法人資料） | 找當天成交裡法人占比最高的股票 |
| 量比（20 日） | 今天成交金額 ÷ 前 20 個交易日平均（至少要有 10 天）＊ | 找比平常突然熱絡的股票 |
| 5 日 / 20 日漲幅 | 收盤 ÷ 5 / 20 個交易日前的收盤 − 1 ＊ | 找近一週、近一個月最強的股票 |
| 法人連續買超天數 | 三大法人連續買超幾天，連續賣超為負數，最多往前看 60 天 ＊ | 找法人持續布局的股票 |
| 法人 5 日買超金額 | 最近 5 天（買賣超股數 × 當天收盤）加總 ＊ | 找法人近一週投入最多錢的股票 |

另有「新高」篩選（需自動資料），用**收盤價**跟前 N 個交易日的最高收盤比較，期間可選 20 日、60 日、一年（240 日）或資料期間（目前能判斷的歷史新高）：

- **創新高**：收盤高於前高，並可設定「高出至少幾 %」（預設 0，也就是只要突破就算）。
- **接近新高**：收盤在前高下方幾 % 以內、還沒突破（預設 5 %）。

開啟篩選後，明細表會多一欄「距前高 %」：正數為高出前高幾 %，負數為離前高還差幾 %。

＊ 歷史比較的項目只在網頁版的自動資料可用，由每天抓資料時一併算好（`data/hist/`）。價格未還原除權息，跨除權息日的漲幅會偏低。

另有「產業」選單，可勾選一個或多個產業（例如半導體業、電子零組件業），選「只保留」只留這些產業的股票，選「排除」則去掉這些產業；不勾為全部。產業分類來自證交所的 ISIN 證券代碼表，每週自動更新一次。直接打開本機的 `index.html` 時沒有這個選單。

名單規則：只取四位數普通股、當天有成交，依所選項目由大到小排序，同值再依成交金額。依成交金額以外的項目排序時，會先排除成交金額低於「最低成交金額」（預設 0.5 億）的股票，避免冷門股擠進名單。勾選「只保留三大法人買超」時，先排除三大法人賣超或當天沒有法人進出的股票；沒放法人檔的市場不做這項篩選。檔案只在你的瀏覽器裡處理，不會上傳。

### 手動放檔（備用）

自動資料某天沒抓到時，可以把資料來源切到「手動放檔」，自己下載交易所的檔案：

1. 收盤後下載每日行情（必填，要同一天）：
   - 上市：[證交所每日收盤行情](https://www.twse.com.tw/zh/trading/historical/mi-index.html)。分類項目選「全部(不含大盤、指數、權證、牛熊證、可展延牛熊證)」，查詢後按「CSV 下載」，檔名是 `MI_INDEX` 開頭。
   - 上櫃：[櫃買中心上櫃股票行情](https://www.tpex.org.tw/zh-tw/mainboard/trading/info/pricing.html)。選日期後下載 CSV，檔名是 `RSTA3104` 開頭。不要下載成興櫃行情，工具會擋下來。
2. 想只看法人在買的股票，再下載三大法人檔（選填）：
   - 上市：[證交所三大法人買賣超日報](https://www.twse.com.tw/zh/trading/foreign/t86.html)。分類項目選「全部(不含權證、牛熊證、可展延牛熊證)」，查詢後按「CSV 下載」。
   - 上櫃：[櫃買中心三大法人買賣明細](https://www.tpex.org.tw/zh-tw/mainboard/trading/major-institutional/detail/day.html)。選日期後下載 CSV，檔名是 `BIGD_` 開頭。
3. 打開網頁版，資料來源選「手動放檔」（或直接打開本機的 `index.html`），把檔案拖進對應的格子：上市、上櫃各有「每日行情」和「三大法人」兩格。只放上市或只放上櫃也可以。

歷史比較的排序與新高篩選只有自動資料能用。

## 自動資料

GitHub Actions 每個交易日台北時間 18:00（GitHub 排程可能延遲）執行 `scripts/fetch_daily.py`，從證交所與櫃買中心抓取當天的行情與三大法人資料，存成 `data/YYYY-MM-DD.json` 並提交到 repo。網頁版打開時會直接讀取這些資料，不需要下載任何檔案。

- **重抓某幾天：** 到 repo 的 **Actions → 抓取每日行情 → Run workflow**，在「補抓日期」填 `2026-10-01` 這樣的日期（多個用空白分隔），留空為今天。
- **補抓一段期間：** 到 **Actions → 補抓歷史資料 → Run workflow**，填最早日期（例如一年前）。會從昨天往回抓，已有的日期自動跳過，每 40 分鐘提交一次進度。請求之間至少間隔 4 秒；遇到阻擋時會等 1、3、10 分鐘再試，連續失敗就先停下，之後再執行一次即可從中斷處繼續。
- **抓取失敗：** 交易所偶爾會擋雲端主機的連線，Actions 會標示失敗並寄信通知。過一陣子用上面的方式重抓，或當天改用「手動放檔」。三大法人若當天還沒公布，該部分會存成空的，網頁上會提示。
- **在自己電腦上抓：** `python scripts/fetch_daily.py 2026-10-02`，或補抓一段期間 `python scripts/fetch_daily.py --since 2026-09-01`，只需要 Python 3，不用安裝其他套件。補抓大量資料建議用 GitHub Actions，萬一被交易所擋下，被擋的是雲端主機而不是你的網路。
- **自己架一份：** fork 本專案後，在 **Settings → Pages** 選 **Deploy from a branch**、分支 `main`、資料夾 `/ (root)`，並確認 **Actions** 已啟用。

直接打開本機的 `index.html` 讀不到自動資料（瀏覽器限制），會自動改用手動放檔。

## 演算法

結構與 OB 的取法參考 [LuxAlgo "Smart Money Concepts"](https://www.tradingview.com/script/CnB3fSph-Smart-Money-Concepts-LUX/) 公開的演算法重新實作；「價格進入 OB」的判定是本專案自行加上的。

1. **Swing 高低點**：用狀態機判定。當 N 根前的高點高於最近 N 根的最高價，就把它登記為 swing 高點，低點同理。Internal 用 N = 5，Swing 用 N = 50。
2. **結構破壞（BOS / CHoCH）**：收盤價向上穿越最近一個還沒被穿越過的 swing 高點，視為向上結構破壞；向下同理。Internal 層級另外要求它的高點不等於 Swing 層級的高點。
3. **Order Block**：結構破壞發生時，在 swing 點到破壞前一根之間，找出最低的那根 K（多方）或最高的那根 K（空方），用它的高低點當作 OB 區間。振幅大於 2 倍 ATR(200) 的 K 棒不會被選中。
4. **失效**：多方 OB 在最低價跌破下緣時移除（Close 模式則看收盤價），空方 OB 相反。
5. **進入訊號**：價格從 OB 外面進入未失效 OB 區間的那一根 K 棒觸發。

SMC 沒有統一的標準定義，本實作不追求跟 LuxAlgo 的圖一模一樣。

## 疑難排解

**表格說某檔有 OB，圖上卻看不到。**
先確認兩件事：圖表週期是否跟掃描週期相同，以及圖上的指標是否用相同的結構層級與長度。週期不同，OB 本來就不同。也可能是下方「已知問題」第 1 點造成的。

**圖表只能放大縮小，不能自由拖動（新帳號常見）。**
這是 TradingView 的圖表設定，跟指標無關。在右側價格軸上按右鍵，取消勾選「鎖定價格對K線比例」即可。

**掃描器轉很久或出現逾時錯誤。**
把「OB 掃描回溯上限」降到 100，或減少同一張圖上的掃描器數量。

**加不了 10 份掃描器 / 建不了 10 個警報。**
TradingView 每張圖可加的指標數與警報數依方案有上限。可以分到多張圖表，或只掃前幾批。

**名單工具說「認不出這個檔案」或「請放到另一格」。**
確認下載的是「快速開始」列的報表，並放進對應的格子（上市 / 上櫃、每日行情 / 三大法人）。上櫃行情不要下載成興櫃行情；上櫃法人不要下載成「外資及陸資買賣超彙總表」（`forg_` 開頭），那份只有外資資料。這兩種工具都會擋下來。

## 已知問題與限制

1. **掃描器與單一商品指標記住的 OB 數量不同。** 指標保留最近 100 個、顯示最新 5 個未失效的；掃描器只保留最近 5 個。當較舊的 OB 還沒失效、又連續出現新 OB 時，兩者顯示的 OB 可能不同。
2. **台股交易時段的影響尚未處理。** 台股一天只有 4.5 小時，1 小時線一天 5 根：ATR(200) 在 1 小時線約等於 40 個交易日，時間尺度偏長；開盤跳空容易被當成過大的 K 棒排除；最後一根只有 30 分鐘，振幅天生偏小；2 小時線切不整齊。
3. **歷史比較只有自動資料能用。** 量比、5 日 / 20 日漲幅、法人連買與 5 日買超需要前幾個交易日的資料，手動放檔時無法計算；自動資料目前從 2025-10-02 開始，最早那幾天也會因為資料不足而算不出來。預設的成交金額排序會讓大型股與當天熱門股排在前面，冷門股不會進名單。
4. **表頭的週期文字固定加上「m」。** 掃 60 分鐘會顯示「60m」，掃日線會顯示成「Dm」，只影響顯示。
5. **訊號尚未經過充分回測。** 本專案不保證「價格進入 OB」有任何統計上的優勢，使用前請自行驗證。
